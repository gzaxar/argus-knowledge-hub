# Guide: Creating EuPRAXIA Documents in ARGUS

This guide explains how to create standardized EuPRAXIA documents in ARGUS using approved templates and native field types. Follow the relevant project procedures for review, approval, and publication.

## Before you start

- Confirm the document's purpose, audience, owner, and required reviewers.
- Locate the current approved template for the document type. Do not rely on an older document as a template unless its currency is confirmed.
- Gather authoritative source material and check that it is suitable to include.
- Check project requirements for naming, classification, and access before adding content.

## Create the document

1. Open the appropriate document creation workflow in ARGUS.
2. Select the approved EuPRAXIA template that matches the document's purpose. If no suitable template is available, contact the project documentation owner.
3. Enter a clear title and complete required metadata, such as project or work-package association, owner, status, dates, and document identifier where applicable.
4. Fill in the template sections, preserving required headings and instructions. Replace placeholder guidance with the appropriate content.
5. Save the document, then check its content, metadata, links, and access settings.

## Use ARGUS native types

Represent information with the appropriate ARGUS field type when available, rather than putting all data into free text. For example, use date fields for dates, person or organization fields for ownership, status fields for workflow state, and relationship fields to connect related project records. Use text fields for narrative content and attachment fields for supporting files.

Choose values from controlled lists where provided. Follow the prescribed formats for identifiers, dates, and units. Link to existing ARGUS records instead of creating duplicates. Ensure access permissions are suitable before adding sensitive information or attachments.

## Prepare the content

- Follow the template's section order and document-specific instructions.
- Write clearly and consistently, and define abbreviations on first use.
- Distinguish confirmed information from assumptions, estimates, and open questions.
- Cite or link source material where required by the template or project process.
- Use explicit units for measurements and identify missing information rather than guessing.

## Review and publish

Before submitting, verify that the template is current, required sections and metadata are complete, and names, identifiers, dates, units, links, and attachments are correct. Confirm the document owner, status, and access permissions, then assign the required reviewers.

Submit the document through the applicable ARGUS review or approval workflow. Incorporate feedback and change status only as permitted by that workflow. After approval, follow the project's established process for publishing or sharing the document.

## Revisions

Revise the existing ARGUS document where possible so its history and relationships remain available. Record meaningful changes in the designated revision or change-history area, if provided. If a template changes, follow the documentation owner's guidance on updating existing documents; do not silently replace approved records.

If the needed template, field type, or workflow is missing or unclear, contact the ARGUS workspace or EuPRAXIA documentation owner.
